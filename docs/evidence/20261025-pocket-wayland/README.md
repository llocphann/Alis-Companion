# Private Wayland Pocket reproduction

The reproduction separates two platform defects from metadata persistence. It uses synthetic files, an owned nested Niri, a private session bus and the real Companion DropArea. The existing strict Copy/Ignore assertions remain, with additional Aqua/Octo, four-edge, persisted-v1 restart/deduplication, leave, stationary permission-revocation and Move-only cases. Pointer commands wait for a compositor round trip, and the external client signals readiness after exposure and drag startup.

The installed Niri is `8ed0da44d974c32c6877d2f4630c314da0717ecb`, using Smithay `ff5fa7df392cecfba049ffed55cdaa4e98a8e7ef`. Qt/PySide6 is 6.12.0. Product runtime baseline: Companion `5a0fa09a365d847236a8e12e23320b222887d4b4`, host `764496e2ce3ac668bbd859a4e72ee62f4832dc63`. The fixture expansion is pinned by this document's containing commit; runtime and authored assets are unchanged.

`smithay-dnd-target.patch` restores accepted-MIME feedback to Wayland data sources and sends rejection when an offer is disabled. The unmodified private compositor reproduces source-side Ignore despite Copy/finish on the wire. With this patch, the original unchanged C++ and Python proofs both pass. The earlier component comparison uses the same source and `--no-default-features` on both sides; desktop D-Bus/systemd/screencast and full compositor parity are outside that component comparison.

The expanded matrix then exposes a second defect: ordinary Qt drags can retain the executed Copy result when a target rejects the actual drop after `dnd_drop_performed`. `qt6-wayland-cancel.patch` clears that result on cancellation while retaining the distinct toplevel/docking branch. A matching unpatched Qt module reproduces this failure independently of installed-library build flags.

The later [full-default controls](full-default-controls-receipt.json) build both Niri variants with `cargo build --locked --bin niri -j2`, retaining `dbus`, `systemd` and `xdp-gnome-screencast`. Both run as owned nested compositors without `--session`. The unpatched control fails the original acknowledgement oracle; the compositor-only repair fails stationary permission revocation. With both repairs, C++ and PySide6 independently pass all 13 drags, both characters, four edges and persisted-v1 restart/deduplication. Compiling those features does not qualify their desktop services, screencasting or a real session cutover.

Use a fresh source/build pair for each control, or refresh the modified sources' timestamps before an incremental rebuild. A preserved older timestamp caused Cargo to reuse the baseline binary despite an exit-zero build; that identical-hash candidate was rejected. The qualified baseline and repaired binaries have distinct hashes in the receipt. The full-default PipeWire build used an existing matching libclang/resource-header pair, with process-local `LIBCLANG_PATH` and `BINDGEN_EXTRA_CLANG_ARGS=-resource-dir=...`; no compiler or optional package was installed.

Set `LD_LIBRARY_PATH` only in the bounded private test process; set its `PATH` only to the separately built private compositor. Existing system Qt/Wayland development dependencies are required. No install command, host-library replacement or desktop reload is part of this reproduction. Loader logs must confirm the intended private library.
